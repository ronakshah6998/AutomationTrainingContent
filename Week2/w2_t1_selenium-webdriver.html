Setting Up a Maven Project in IntelliJ

Maven is a build tool that manages your project dependencies — no more manually downloading JAR files.

💡
Why Maven? Without Maven, you'd manually download every library (Selenium JAR, TestNG JAR, etc.) and add them to your project one by one. Maven reads your pom.xml and downloads everything automatically from the internet — and keeps versions in sync.

IntelliJ — Step by Step
1

File → New → Project

Choose Maven Archetype. Select JDK 17+. Use archetype maven-archetype-quickstart for a basic structure.

2

Set GroupId & ArtifactId

GroupId: com.yourcompany (like a package name). ArtifactId: selenium-project (your project name). Click Finish.

3

Open pom.xml — Add Selenium dependency

Inside the <dependencies> block, add the Selenium Java dependency. IntelliJ will show a small icon to download it.

4

Reload Maven (Ctrl+Shift+O)

IntelliJ downloads all dependencies from the internet. You'll see them appear under External Libraries in the project panel.

5

Create your first test class in src/test/java

Right-click src/test/java → New → Java Class. Name it FirstTest. You're ready to write Selenium code.

    <groupId>com.yourcompany</groupId>

    <dependencies>

        <!-- Selenium WebDriver -->

            <groupId>org.seleniumhq.selenium</groupId>

        <dependency>
            <groupId>org.testng</groupId>

    </dependencies>

Key rule: Always put test classes in src/test/java, not in src/main/java. The test scope ensures test libraries are only available when running tests — not in the production build.
What is WebDriver?

WebDriver is the interface (contract) that Selenium uses to control browsers. You write code against the interface — the browser driver implements it.

🔌
Key concept: WebDriver is a Java interface — not a class. ChromeDriver, FirefoxDriver, EdgeDriver are the actual classes that implement it. By writing WebDriver driver = new ChromeDriver() you can switch browsers by changing only ChromeDriver to another driver — the rest of your code stays identical.
☕ WebDriver — Initialisation
// WebDriver is an INTERFACE — ChromeDriver implements it
WebDriver driver = new ChromeDriver();

// Same interface — switch to Firefox with one change
WebDriver driver = new FirefoxDriver();

// Same interface — switch to Edge
WebDriver driver = new EdgeDriver();

// All three have identical method signatures:
driver.get("https://example.com");
driver.findElement(By.id("username"));
driver.quit();
Interface vs Class — Why It Matters
☕ Interface polymorphism explained
// ❌ BAD — tightly coupled to Chrome only
ChromeDriver driver = new ChromeDriver();

// ✅ GOOD — uses interface reference (flexible)
WebDriver driver = new ChromeDriver();

// Now you can pass 'driver' to any method that
// accepts WebDriver — completely browser-agnostic
public void loginTest(WebDriver driver) {
    driver.get("https://app.com/login");
    // works with Chrome, Firefox, Edge — anything
}

⚠
quit() vs close(): Always use driver.quit() at the end of your test. close() only closes the active tab — if there are multiple windows, the WebDriver session stays open and ChromeDriver keeps running in the background.
☕ Complete First Test
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class FirstTest {
    public static void main(String[] args) {

        // 1. Create driver — Selenium 4 manages ChromeDriver automatically
        WebDriver driver = new ChromeDriver();

        // 2. Open a URL
        driver.get("https://google.com");

        // 3. Get page title
        String title = driver.getTitle();
        System.out.println("Page title: " + title);

        // 4. Always quit at the end
        driver.quit();
    }
}
Browser Navigation Commands

Selenium gives you full control over browser navigation — open pages, go back, go forward, and refresh, just like a real user would.

get() vs navigate().to()
driver.get()
// Simple — just open a URL
// Waits for page to fully load
driver.get("https://google.com");

// Use this for most navigation
driver.navigate().to()
// Part of the Navigate interface
// Enables back/forward/refresh
driver.navigate().to("https://google.com");

// Same result — different style
All Navigation Commands
☕ Complete Navigation Example
WebDriver driver = new ChromeDriver();

// 1. Open a page
driver.get("https://google.com");
System.out.println("Page 1: " + driver.getTitle());

// 2. Navigate to another page
driver.navigate().to("https://selenium.dev");
System.out.println("Page 2: " + driver.getTitle());

// 3. Go back to Google
driver.navigate().back();
System.out.println("After back: " + driver.getTitle());

// 4. Go forward again
driver.navigate().forward();

// 5. Refresh current page
driver.navigate().refresh();

driver.quit();

Interacting with Web Elements

After finding an element with findElement(), you call actions on it. These three cover 80% of all automation scenarios.

.click()

click()

Simulates a mouse click. Use for buttons, links, checkboxes, radio buttons — anything you'd click.

WebElement btn = driver.findElement(By.id("loginBtn")); btn.click();
.sendKeys()

sendKeys(text)

Types text into an input field, textarea, or any editable element. Simulates real keyboard input.

WebElement field = driver.findElement(By.id("username")); field.sendKeys("admin");
.getText()

getText()

Reads the visible text content of an element. Use for labels, messages, headings — to assert expected output.

String msg = driver.findElement(By.id("status")) .getText(); System.out.println(msg);
.clear()

clear()

Clears the existing content of an input field before typing. Use before sendKeys() when a field might already have a value.

WebElement field = driver.findElement(By.id("search")); field.clear(); // wipe first field.sendKeys("new text");

Real Login Test — All Actions Together
☕ Complete Login Test with All Actions
WebDriver driver = new ChromeDriver();
driver.get("https://app.example.com/login");

// sendKeys — type into username field
driver.findElement(By.id("username")).sendKeys("admin");

// sendKeys — type password
driver.findElement(By.id("password")).sendKeys("secret123");

// click — submit the login form
driver.findElement(By.id("loginBtn")).click();

// getText — read the welcome message shown after login
String message = driver.findElement(By.id("welcomeMsg")).getText();
System.out.println("Welcome text: " + message);

// Assert it contains expected value
Assert.assertTrue(message.contains("Welcome, admin"));

driver.quit();
🔑
By Locators: findElement() always needs a locator strategy. The most common: By.id() (fastest), By.name(), By.className(), By.xpath(), By.cssSelector(), By.linkText(). Prefer By.id() whenever possible — it's the fastest and most stable.

Common Selenium Errors & Fixes

These four errors are what every beginner hits in their first week. Know them now — save hours of debugging later.

🔴 Error: WebDriver Not Initialized (NullPointerException)

What happened?

You declared a WebDriver variable but never assigned it a value. Calling any method on a null reference throws a NullPointerException.

java.lang.NullPointerException: Cannot invoke "WebDriver.get(String)" because "driver" is null at FirstTest.main(FirstTest.java:8)
❌ Wrong
WebDriver driver; // declared, not assigned! driver.get("https://google.com"); // NullPointerException here
✅ Correct
WebDriver driver = new ChromeDriver(); driver.get("https://google.com"); // works perfectly ✓
✅ Fix: Always initialize WebDriver before calling any method on it.
🔴 Error: Wrong Locator — Element Not Found

What happened?

You used By.id("wrongId") but the actual element's id is different. Selenium can't find it, so it throws NoSuchElementException. Always inspect the element in DevTools first.

org.openqa.selenium.NoSuchElementException: no such element: Unable to locate element: {"method":"id","selector":"usrname"} (Session info: chrome=121.0.0)
❌ Wrong (typo in id)
driver.findElement(By.id("usrname")) .sendKeys("admin"); // actual id is "username"
✅ Correct (exact match)
driver.findElement(By.id("username")) .sendKeys("admin"); // matches HTML id="username" ✓
✅ Fix: Open DevTools (F12), right-click the element → Inspect. Copy the exact id/name/class attribute.
🔴 Error: NoSuchElementException — Element Timing Issue

What happened?

Selenium tries to find an element before it appears on the page. This happens frequently with dynamic content, modals, or elements that load after an API call. The locator itself might be correct — timing is the problem.

org.openqa.selenium.NoSuchElementException: no such element: Unable to locate element: {"method":"id","selector":"welcomeMsg"} The element might not be in the DOM yet — try adding an explicit wait.
❌ Wrong (no wait)
driver.findElement(By.id("loginBtn")).click(); // instantly tries to find welcome msg driver.findElement(By.id("welcomeMsg")).getText();
✅ Correct (with wait)
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10)); wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("welcomeMsg"))); driver.findElement(By.id("welcomeMsg")).getText();
✅ Fix: Use ExplicitWait (WebDriverWait) to wait for the element to be visible before acting on it.
🔴 Error: ElementNotInteractableException

What happened?

Selenium found the element in the DOM but it's hidden, overlapped by another element, or disabled. You can't click or type into it yet. Often caused by overlays, animations, or conditional visibility.

org.openqa.selenium.ElementNotInteractableException: element not interactable (Session info: chrome=121.0.0) Element is found but not visible/enabled — it may be hidden by CSS or covered by another element.
❌ Wrong (element hidden)
// Element exists in DOM but is display:none driver.findElement(By.id("hiddenInput")) .sendKeys("text"); // Exception!
✅ Correct (wait for visible)
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(5)); wait.until(ExpectedConditions .elementToBeClickable(By.id("hiddenInput"))); driver.findElement(By.id("hiddenInput")).sendKeys("text");
✅ Fix: Use ExpectedConditions.elementToBeClickable() — it waits until the element is both visible and enabled.
