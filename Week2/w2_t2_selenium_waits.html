What is Implicit Wait? global setting

A single line that applies a waiting behaviour to every element lookup in your test session.

◷
You tell Selenium: "If you can't find an element right now, keep trying for up to N seconds before giving up." You write this once, and it applies to every single element lookup in your test.
☕ Implicit Wait — Java 
// Step 1: Create driver
WebDriver driver = new ChromeDriver();

// Step 2: Set the wait — write this ONCE
driver.manage().timeouts()
    .implicitlyWait(Duration.ofSeconds(10));

// Step 3: Now use driver normally
// Selenium will auto-wait up to 10s for each element
driver.findElement(By.id("username"))
    .sendKeys("admin@test.com");

driver.findElement(By.id("password"))
    .sendKeys("Pass@123");

driver.findElement(By.id("loginBtn"))
    .click();

Pros and Cons
Very simple — one line of code, works everywhere
No need to repeat wait code for each element
Only checks if element EXISTS in page — not if it is visible or clickable
Can find a disabled button and try to click it — test crashes
Do NOT mix with explicit wait — causes unpredictable timeouts
What is Explicit Wait? recommended

Fine-grained per-element waiting with full control over what "ready" means for each interaction.

◎
You tell Selenium: "Wait for THIS specific condition on THIS specific element — check every 500ms, give up after N seconds." You are in full control of what "ready" means.
☕ Explicit Wait — Java 
// Step 1: Create driver
WebDriver driver = new ChromeDriver();

// Step 2: Create a wait object — 10 second limit
WebDriverWait wait = new WebDriverWait(
    driver, Duration.ofSeconds(10)
);

// Step 3: Use wait.until() with a condition
// "Wait until username field is VISIBLE, then type"
wait.until(ExpectedConditions
    .visibilityOfElementLocated(By.id("username")))
    .sendKeys("admin@test.com");

// "Wait until login button is CLICKABLE, then click"
wait.until(ExpectedConditions
    .elementToBeClickable(By.id("loginBtn")))
    .click();

        🚫
        
Golden rule: Never use implicit and explicit wait together in the same test. Selenium merges the timeouts in unexpected ways and your tests become unpredictable.

      


      

        ⚠️
        
What about Thread.sleep()? Avoid it in real tests. It always waits the full time — even if the element is ready in 0.1 seconds. Use only for quick debugging, never in final code.
