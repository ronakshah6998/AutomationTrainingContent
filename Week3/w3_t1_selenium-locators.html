What is a Locator?

A locator is the strategy Selenium uses to identify a specific HTML element on a webpage. Without a locator, Selenium has no idea which element to interact with.

💡
Real-world analogy: Think of a webpage as a city and elements as buildings. A locator is the address you give Selenium so it can navigate directly to the right building — without wandering the entire city. A good locator is precise (goes to the right place) and stable (doesn't change when the city is redesigned).
The DOM — Where Elements Live

The DOM (Document Object Model) is the browser's internal representation of a webpage as a tree of elements. Selenium traverses this tree using locators to find elements.

Simple Attribute Locators

These three are the simplest locators — they match a specific attribute value on the element directly.

By.id()

ID Locator

Matches the element whose id attribute equals the given value. IDs are unique per page — making this the most reliable locator.

// HTML: <input id="username"> driver.findElement(By.id("username"));
By.name()

Name Locator

Matches elements by their name attribute. Common in form inputs. Not always unique — multiple elements can share a name.

// HTML: <input name="email"> driver.findElement(By.name("email"));
By.className()

Class Locator

Matches elements by CSS class name. Classes are often shared across many elements — use carefully and only when the class is specific enough.

// HTML: <button class="btn-primary"> driver.findElement(By.className("btn-primary"));
Complete Code Examples

WebDriver driver = new ChromeDriver();

// By.partialLinkText — partial anchor text
driver.findElement(By.partialLinkText("Forgot")).click();

CSS Selectors in Selenium

CSS Selectors are the same patterns used to style web pages — and they work in Selenium too. Faster than XPath in most browsers and very readable.

🎨
Why CSS Selectors? They are faster than XPath in Chrome and Firefox. They support complex patterns combining tag, id, class, and attributes. They're concise and widely understood by both developers and testers.

// 1. Tag + ID (# means ID)
driver.findElement(By.cssSelector("input#username"));

// 2. Tag + Class (. means class)

// 7. Parent → Child (space = descendant)
driver.findElement(By.cssSelector("form#loginForm input#username"));

// 8. Direct child (>)
driver.findElement(By.cssSelector("div.container > form > input"));

What is XPath?

XPath (XML Path Language) is a query language for finding nodes in XML/HTML. It's the most powerful locator strategy — but also the most complex.

🌐
CSS vs XPath: CSS Selectors can only traverse downward in the DOM (parent to child). XPath can also go upward (child to parent), traverse siblings, and find elements by text content — making it essential for complex scenarios that CSS cannot handle.

XPath Basics — Code Examples
☕ XPath Basics in Java
// 1. By attribute (most common)
driver.findElement(By.xpath("//input[@id='username']"));
driver.findElement(By.xpath("//input[@name='email']"));
driver.findElement(By.xpath("//input[@type='text']"));

// 2. By visible text
driver.findElement(By.xpath("//button[text()='Login']"));

// 3. Combining tag + attribute
driver.findElement(By.xpath("//form[@id='loginForm']//input"));

// 4. Navigate up (parent) — CSS can't do this!
driver.findElement(By.xpath("//label[text()='Username']/../input"));

// 5. Nth element using index
driver.findElement(By.xpath("(//input[@type='text'])[2]")); // 2nd text input
🌲
Remember: In XPath, // means "anywhere in the document". / (single slash) means "direct child". So //form//input finds any input inside any form, while //form/input finds only inputs that are direct children of a form.
Why Dynamic XPath?

Modern web apps generate element attributes dynamically — ids change on every page load. Dynamic XPath uses functions instead of exact values to locate these elements reliably.

⚡
The problem: Many frameworks (Angular, React) generate ids like id="username-abc123xyz" where the suffix changes each time. You can't use By.id("username-abc123xyz") because tomorrow it will be different. Dynamic XPath uses contains() to match just the stable part.
The Four Dynamic XPath Functions
1

contains() — Partial match on any attribute or text

Matches when the attribute contains the given string. Perfect for dynamic ids with changing suffixes.

2

starts-with() — Match by prefix

Matches when the attribute starts with a fixed prefix. More precise than contains() when only the suffix varies.

3

text() — Match by visible text

Matches elements by their visible text content. Great for buttons and links whose text is stable even when other attributes change.

4

and / or — Combine multiple conditions

Use and to narrow down results when a single attribute isn't unique enough. Target the element using two attributes simultaneously.

Dynamic XPath — All Patterns with Code
☕ Dynamic XPath — Complete Examples
// 1. contains() on attribute
// HTML: <input id="username-abc123"> — suffix changes each load
driver.findElement(By.xpath("//input[contains(@id,'username')]"));

// 2. starts-with() on attribute
// HTML: <input id="user_field_999">
driver.findElement(By.xpath("//input[starts-with(@id,'user_')]"));

// 3. contains() on text
// Button text might be "Login Now" or "Login Here"
driver.findElement(By.xpath("//button[contains(text(),'Login')]"));

// 4. Exact text match
driver.findElement(By.xpath("//button[text()='Submit']"));

// 5. AND — both conditions must match
driver.findElement(By.xpath("//input[@type='text' and @name='email']"));

// 6. OR — either condition matches
driver.findElement(By.xpath("//input[@type='text' or @type='email']"));

// 7. contains() on class (partial class name)
// HTML: <button class="btn btn-primary large">
driver.findElement(By.xpath("//button[contains(@class,'btn-primary')]"));

// 8. Real project — React dynamic ID
// HTML: <input id="react-select-3-input">
driver.findElement(By.xpath("//input[contains(@id,'react-select') and contains(@id,'input')]"));

Best practice: When writing dynamic XPath, always target the most stable part of an attribute. Usually the beginning of an id or class is set by developers and stays fixed — only auto-generated suffixes change. Use starts-with() or contains() on that stable part.

Common Locator Mistakes

These five mistakes are responsible for most "element not found" failures. Know each one — prevent hours of debugging.

🔴 Mistake: Wrong XPath Syntax

What happened?

A common syntax error is missing // at the start, forgetting @ before attribute names, or using the wrong quote style inside XPath strings.

org.openqa.selenium.InvalidSelectorException: invalid selector: Unable to locate an element with the xpath expression input[@id='username'] — missing leading //
❌ Wrong syntax
driver.findElement(By.xpath("input[@id='username']")); // Missing leading // driver.findElement(By.xpath("//input[id='username']")); // Missing @ before id
✅ Correct syntax
driver.findElement(By.xpath("//input[@id='username']")); // // + @ = correct driver.findElement(By.xpath("//button[text()='Login']")); // text() doesn't use @
✅ Rule: XPath must start with //. Attributes need @prefix. text() is a function — no @.
🔴 Mistake: Using Dynamic IDs Directly

What happened?

Frameworks like React, Angular, and Vue often generate IDs automatically with a different suffix on every page load. Using the full ID will work in dev but fail in CI or the next day.

NoSuchElementException: no such element: Unable to locate element by: id "username-xk92ms3p" The auto-generated suffix "xk92ms3p" is different on every page load.
❌ Fragile (full dynamic id)
driver.findElement(By.id("username-xk92ms3p")); // Breaks on next page load!
✅ Stable (contains)
driver.findElement(By.xpath( "//input[contains(@id,'username')]")); // Matches any id containing "username" ✓
✅ Fix: Use contains() or starts-with() on the stable prefix of dynamic attributes.
🔴 Mistake: Multiple Classes in By.className()

What happened?

By.className() accepts exactly ONE class name. Passing multiple classes (with a space) throws an exception because Selenium interprets spaces as part of the class name.

org.openqa.selenium.InvalidSelectorException: Compound class names not permitted className "btn btn-primary" contains a space — that is not a valid single class name.
❌ Multiple classes (space)
// HTML: class="btn btn-primary" driver.findElement( By.className("btn btn-primary")); // Exception — space not allowed!
✅ Use CSS Selector
// Use CSS for multiple classes driver.findElement( By.cssSelector(".btn.btn-primary")); // dot.dot = multiple classes ✓
✅ Fix: Use By.cssSelector(".class1.class2") to match elements with multiple classes.
🔴 Mistake: Using Absolute XPath in Real Projects

What happened?

Absolute XPath starts from the root /html/body/… and lists every level. Adding even a single div wrapper anywhere in the page breaks the entire locator.

NoSuchElementException: no such element The developer added a wrapper div — now the absolute path is wrong: /html/body/div[1]/form/input[1] → doesn't exist anymore
❌ Absolute XPath
driver.findElement(By.xpath( "/html/body/div/form/input[1]")); // Breaks if ANY parent changes
✅ Relative XPath
driver.findElement(By.xpath( "//input[@id='username']")); // Independent of DOM structure ✓
✅ Fix: Always write relative XPath starting with //. Never use absolute XPath in automation.
🔴 Mistake: Quote Conflict in XPath Strings

What happened?

In Java, XPath strings are wrapped in double quotes. If the XPath value also uses double quotes, the Java string terminates early — causing a compile error or invalid XPath.

Compile error: String literal is not properly closed driver.findElement(By.xpath("//input[@id="username"]")); ← the inner " ends the Java string
❌ Conflicting quotes
driver.findElement(By.xpath( "//input[@id="username"]")); // Double inside double = broken!
✅ Use single quotes inside
driver.findElement(By.xpath( "//input[@id='username']")); // Outer = double, inner = single ✓
✅ Rule: XPath string is wrapped in Java double quotes. Always use single quotes inside XPath for attribute values.
