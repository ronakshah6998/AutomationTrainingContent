What are Checkboxes?

Checkboxes are form controls that let users select one or more options independently. Each checkbox works on its own — checking one does not affect others.

☑️

Checkbox

A square-shaped toggle. Can be checked or unchecked. Multiple checkboxes can be selected at the same time. HTML: <input type="checkbox">

🔘

Radio Button

A circular toggle. Grouped by name attribute. Only ONE can be selected at a time in a group. HTML: <input type="radio">

🎯

isSelected()

Selenium method that returns true if the element is currently checked/selected. Works on both checkboxes and radio buttons.

🖱️

click() to Toggle

Use click() to check or uncheck. Always verify the state with isSelected() BEFORE clicking to avoid toggling unexpectedly.

Why Selenium provides dedicated handling: Checkboxes and radio buttons are NOT regular buttons. Clicking them is not enough — you need to verify their state before and after. Selenium's isSelected() method gives you this power, letting you write reliable, state-aware automation.
Checkbox Handling in Selenium

Learn how to locate, click, verify, and manage checkboxes reliably using Selenium WebDriver.

🔌
Core idea: A checkbox is just an <input type="checkbox"> element. Selenium finds it like any other element using findElement(), then uses click() to toggle it and isSelected() to read its state.
Step 1 — Locating Checkboxes
1

By ID (Fastest and most reliable)

Use By.id("termsCheckbox") when the checkbox has a unique ID attribute. Always prefer ID when available.

2

By Name

Use By.name("newsletter") when multiple checkboxes share a name. Good for grouped checkboxes in forms.

3

By CSS Selector

Use By.cssSelector("input[type='checkbox']") for type-based selection. More flexible than ID when no ID is available.

4

By XPath

Use By.xpath("//input[@type='checkbox' and @id='terms']") for complex conditions. Most powerful but slightly slower.

☕ Locating Checkboxes — All 4 Strategies
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.By;
import org.openqa.selenium.chrome.ChromeDriver;

public class CheckboxLocators {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://example-registration.com");

        // 1. By ID — fastest, most reliable
        WebElement cbById = driver.findElement(By.id("termsCheckbox"));

        // 2. By Name — useful for grouped checkboxes
        WebElement cbByName = driver.findElement(By.name("newsletter"));

        // 3. By CSS Selector — type-based selection
        WebElement cbByCss = driver.findElement(By.cssSelector("input[type='checkbox']"));

        // 3b. CSS — with specific ID
        WebElement cbByCssId = driver.findElement(By.cssSelector("input#termsCheckbox"));

        // 4. By XPath — most flexible
        WebElement cbByXpath = driver.findElement(By.xpath("//input[@type='checkbox' and @id='terms']"));

        // 4b. XPath by visible label text
        WebElement cbByLabel = driver.findElement(
            By.xpath("//label[contains(text(),'Terms')]/preceding-sibling::input"));

        driver.quit();
    }
}
Clicking a Checkbox + State Verification
☕ click() + isSelected() — The Right Pattern
public class CheckboxClick {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://example-registration.com");

        WebElement termsCheckbox = driver.findElement(By.id("termsCheckbox"));

        // ✅ Step 1: Check current state BEFORE clicking
        boolean isAlreadyChecked = termsCheckbox.isSelected();
        System.out.println("Before click: " + isAlreadyChecked); // false

        // ✅ Step 2: Click only if not already checked
        if (!isAlreadyChecked) {
            termsCheckbox.click();
            System.out.println("Checkbox was unchecked. Now clicking to check it.");
        } else {
            System.out.println("Checkbox already checked. No action needed.");
        }

        // ✅ Step 3: Verify final state after click
        boolean isNowChecked = termsCheckbox.isSelected();
        System.out.println("After click: " + isNowChecked); // true

        // Assert using TestNG or manual check
        if (isNowChecked) {
            System.out.println("✅ PASS — Terms checkbox is now checked");
        } else {
            System.out.println("❌ FAIL — Terms checkbox NOT checked");
        }

        driver.quit();
    }
}
⚠
Golden Rule: Always call isSelected() BEFORE calling click() on a checkbox. If you blindly click an already-checked checkbox, you will accidentally UNCHECK it — breaking your test.
Selecting Multiple Checkboxes
☕ Multiple Checkboxes — Individual & Loop Approach
import java.util.List;

public class MultipleCheckboxes {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://example-registration.com");

        // ── Approach 1: Select each checkbox individually ──
        WebElement cbTerms = driver.findElement(By.id("termsCheckbox"));
        WebElement cbNewsletter = driver.findElement(By.id("newsletterCheckbox"));
        WebElement cbSMS = driver.findElement(By.id("smsCheckbox"));

        if (!cbTerms.isSelected())      cbTerms.click();
        if (!cbNewsletter.isSelected()) cbNewsletter.click();
        if (!cbSMS.isSelected())        cbSMS.click();

        // ── Approach 2: Select ALL checkboxes using a loop ──
        List<WebElement> allCheckboxes =
            driver.findElements(By.cssSelector("input[type='checkbox']"));

        for (WebElement checkbox : allCheckboxes) {
            if (!checkbox.isSelected()) {   // only click if not already checked
                checkbox.click();
            }
        }
        System.out.println("All checkboxes selected. Count: " + allCheckboxes.size());

        // ── Approach 3: Deselect ALL checkboxes ──
        for (WebElement checkbox : allCheckboxes) {
            if (checkbox.isSelected()) {    // only click if currently checked
                checkbox.click();
            }
        }
        System.out.println("All checkboxes deselected.");

        driver.quit();
    }
}

✅
Best Practice: Wrap checkbox interactions in a utility method that always checks state first. This pattern prevents accidental toggling and makes your tests deterministic — they produce the same result no matter what state the page starts in.
☕ Best Practice — Reusable Checkbox Utility Method
public class CheckboxUtils {

    /**
     * Ensures a checkbox is CHECKED.
     * If already checked — does nothing. If unchecked — clicks it.
     */
    public static void selectCheckbox(WebElement checkbox) {
        if (!checkbox.isSelected()) {
            checkbox.click();
            System.out.println("✅ Checkbox checked.");
        } else {
            System.out.println("ℹ️ Checkbox was already checked. Skipped.");
        }
    }

    /**
     * Ensures a checkbox is UNCHECKED.
     * If already unchecked — does nothing. If checked — clicks it.
     */
    public static void deselectCheckbox(WebElement checkbox) {
        if (checkbox.isSelected()) {
            checkbox.click();
            System.out.println("✅ Checkbox unchecked.");
        } else {
            System.out.println("ℹ️ Checkbox was already unchecked. Skipped.");
        }
    }

    // Usage:
    public static void main(String[] args) {
        WebDriver driver = new ChromeDriver();
        driver.get("https://example.com/register");

        WebElement terms = driver.findElement(By.id("terms"));
        selectCheckbox(terms);      // Always ends up checked

        WebElement newsletter = driver.findElement(By.id("newsletter"));
        deselectCheckbox(newsletter); // Always ends up unchecked

        driver.quit();
    }
}
Radio Button Handling in Selenium

Radio buttons are grouped controls where only one option can be selected at a time. Understanding the grouping mechanism is key to automating them correctly.

🔌
How radio buttons work internally: All radio buttons in the same group share the same name attribute. When the browser detects a click on one radio button, it automatically deselects all others with the same name. Selenium just calls click() — the browser does the deselection logic.
Radio Button Group — How the browser links them
<input type="radio" name="gender" id="male" value="M" /> Male
<input type="radio" name="gender" id="female"value="F" /> Female
<input type="radio" name="gender" id="other" value="O" /> Other
name="gender" is the group identifier. All three share it → they form one radio group → only one can be selected at a time.
Selecting Radio Buttons — All Locator Strategies
☕ Radio Button — Locating and Selecting
public class RadioButtonHandling {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://example.com/register");

        // ── Method 1: By ID (most reliable) ──
        WebElement rbMale = driver.findElement(By.id("male"));

        // ── Method 2: By name + value (CSS) ──
        WebElement rbFemale = driver.findElement(
            By.cssSelector("input[name='gender'][value='F']"));

        // ── Method 3: By XPath with value attribute ──
        WebElement rbOther = driver.findElement(
            By.xpath("//input[@type='radio' and @value='O']"));

        // ── Method 4: By label text (XPath) ──
        WebElement rbByLabel = driver.findElement(
            By.xpath("//label[text()='Female']/preceding-sibling::input[@type='radio']"));

        // ── Selecting a radio button ──
        if (!rbMale.isSelected()) {   // check current state first
            rbMale.click();             // select Male
        }

        // ── Verify selection ──
        System.out.println("Male selected:   " + rbMale.isSelected());   // true
        System.out.println("Female selected: " + rbFemale.isSelected()); // false
        System.out.println("Other selected:  " + rbOther.isSelected());  // false

        // ── Now switch to Female ──
        rbFemale.click(); // browser auto-deselects Male

        System.out.println("Male selected:   " + rbMale.isSelected());   // false
        System.out.println("Female selected: " + rbFemale.isSelected()); // true

        driver.quit();
    }
}
Reading All Radio Buttons in a Group
☕ Finding Which Radio Button is Currently Selected
import java.util.List;

public class RadioGroupHandling {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://example.com/register");

        // Get ALL radio buttons in the "gender" group
        List<WebElement> genderRadios =
            driver.findElements(By.cssSelector("input[name='gender']"));

        System.out.println("Total gender options: " + genderRadios.size()); // 3

        // Find which one is currently selected
        for (WebElement radio : genderRadios) {
            if (radio.isSelected()) {
                String value = radio.getAttribute("value");
                System.out.println("Currently selected: " + value);
            }
        }

        // Select radio button by VALUE dynamically
        String targetGender = "F"; // coming from test data
        WebElement targetRadio = driver.findElement(
            By.cssSelector("input[name='gender'][value='" + targetGender + "']"));

        if (!targetRadio.isSelected()) {
            targetRadio.click();
        }
        System.out.println("Selected: " + targetGender);

        driver.quit();
    }
}
✅
Best Practice: Use findElements() (plural) to get all radio buttons in a group. Loop through them, compare the value attribute with your expected value, and call click() only on the matching one. This is data-driven and reusable.
⚠
Cannot deselect a radio button directly: Unlike checkboxes, you cannot uncheck a radio button by clicking it again. The only way to "deselect" a radio button is to select another one in the group. This is browser behaviour — not a Selenium limitation.

import java.util.Arrays;
import java.util.List;

public class ShoppingFilterTest {
    public static void main(String[] args) {

        WebDriver driver = new ChromeDriver();
        driver.get("https://shop.example.com/electronics");

        // Brands we want to select
        List<String> brandsToSelect = Arrays.asList("Samsung", "Sony", "LG");

        // Get all brand checkboxes in the filter panel
        List<WebElement> brandCheckboxes =
            driver.findElements(By.cssSelector(".brand-filter input[type='checkbox']"));

        for (WebElement cb : brandCheckboxes) {
            // Get the value or data-brand attribute for matching
            String brandName = cb.getAttribute("data-brand");

            if (brandsToSelect.contains(brandName)) {
                if (!cb.isSelected()) {
                    cb.click();
                    System.out.println("Selected brand: " + brandName);
                }
            } else {
                // Deselect if not in our target list
                if (cb.isSelected()) {
                    cb.click();
                    System.out.println("Deselected brand: " + brandName);
                }
            }
        }

        driver.quit();
    }
}

Common Mistakes in Checkbox & Radio Handling

Every real Selenium engineer has made these mistakes. Learn what went wrong, how to fix it, and what to say in interviews.

☑ Mistake 1 — Clicking an Already-Checked Checkbox

What happens

If you blindly call click() without checking the current state, you may accidentally uncheck a checkbox that was already checked.

// Before click: checkbox is ALREADY checked (true) // After blind click: checkbox becomes UNCHECKED (false) // Test passes but form behaviour is wrong!
❌ Wrong
WebElement cb = driver.findElement(By.id("terms")); cb.click(); // ← blindly clicking — dangerous!
✅ Correct
WebElement cb = driver.findElement(By.id("terms")); if (!cb.isSelected()) { cb.click(); // only click if unchecked }
✅ Fix: Always call isSelected() before click()
 
🎯 Interview: "Why not just call click() on a checkbox?" — Because if it's already checked, click() will uncheck it, reversing the intended state.
🔍 Mistake 2 — Skipping isSelected() for Verification

What happens

Many beginners click a checkbox and assume it worked. Without calling isSelected() after the click, you have no assertion — the test passes even if the click failed silently.

// Click happened — but did the checkbox actually check? // Maybe JS intercepted. Maybe CSS overlay caught the click. // Without isSelected() check, we'll never know!
❌ Wrong
WebElement cb = driver.findElement(By.id("terms")); cb.click(); // No verification — risky!
✅ Correct
cb.click(); boolean checked = cb.isSelected(); Assert.assertTrue(checked, "Terms checkbox should be checked!");
✅ Fix: Always assert with isSelected() after clicking
 
🎯 Interview: "How do you verify a checkbox is checked?" — Use isSelected() and assert it returns true.
❌ Mistake 3 — Wrong XPath for Checkbox

What happens

Using a label's XPath instead of the actual input element's XPath. Labels are not interactable for isSelected().

org.openqa.selenium.ElementNotInteractableException: element not interactable — element is <label> not <input>
❌ Wrong
// This finds the LABEL, not the checkbox! driver.findElement( By.xpath("//label[@for='terms']")) .isSelected(); // Exception!
✅ Correct
// Find the INPUT element itself driver.findElement( By.xpath( "//input[@type='checkbox' and @id='terms']" )).isSelected(); // works!
✅ Fix: XPath must target <input type="checkbox"> not <label>
 
🎯 Interview: "isSelected() threw an exception on a label element — why?" — isSelected() only works on input[type=checkbox] and input[type=radio].
👻 Mistake 4 — Hidden Checkbox (Styled with CSS)

What happens

Modern UI frameworks (React, Angular, Vue) often hide the real <input> element and use a styled <div> or <span> as the visual checkbox. Clicking the hidden input throws an exception.

org.openqa.selenium.ElementNotInteractableException: element not interactable — element has zero dimensions or is hidden
❌ Wrong
// Tries to click the hidden real input driver.findElement( By.cssSelector("input[type='checkbox']")) .click(); // ← hidden!
✅ Correct
// Click the visible styled element instead driver.findElement( By.cssSelector("label[for='terms']")) .click(); // OR use JavaScript executor ((JavascriptExecutor)driver).executeScript( "arguments[0].click();", hiddenCheckbox);
✅ Fix: Click the associated <label> or use JavascriptExecutor
 
🎯 Interview: "How do you click a hidden checkbox?" — Click its label, or use JavascriptExecutor to call click() programmatically, bypassing visibility constraints.
🏷️ Mistake 5 — Clicking Label Instead of Input for isSelected()

What happens

Clicking a label works for toggling. But calling isSelected() on a label always returns false — isSelected() only works on the actual input element.

// Clicking label toggles the checkbox — OK for click() // But isSelected() on label always returns false — WRONG!
❌ Wrong
WebElement label = driver.findElement( By.cssSelector("label[for='terms']")); label.click(); // works to toggle label.isSelected(); // always false!
✅ Correct
// Click label to toggle (OK) driver.findElement( By.cssSelector("label[for='terms']")) .click(); // isSelected() on the INPUT (correct) boolean state = driver.findElement( By.id("terms")).isSelected();
✅ Fix: Always call isSelected() on the <input> element, not <label>
 
🎯 Interview: "Can you call isSelected() on a label?" — No. isSelected() only works on <input type='checkbox'> and <input type='radio'> elements.
🔄 Mistake 6 — Dynamic IDs

What happens

Some frameworks generate IDs dynamically. The ID changes on every page load, making locators by ID fragile and unreliable.

org.openqa.selenium.NoSuchElementException: Unable to locate element: #checkbox_7f3a2_terms (ID changes on each page load!)
❌ Wrong
// Dynamic ID — breaks on every run driver.findElement( By.id("checkbox_7f3a2_terms"));
✅ Correct
// Use stable attributes instead driver.findElement( By.cssSelector("input[name='terms']")); // OR by label text driver.findElement( By.xpath("//label[contains(text(),'Terms')]" + "/preceding-sibling::input"));
✅ Fix: Use name, value, data-* attributes, or label text — not dynamic IDs
 
🎯 Interview: "How do you handle checkboxes with dynamic IDs?" — Use stable attributes like name, value, data-testid, or navigate via the visible label text using XPath.
🔒 Mistake 7 — Radio Button Not Clickable Due to Overlay

What happens

A loading spinner, tooltip, modal, or cookie banner overlays the radio button. Selenium finds the element but cannot click it because another element intercepts the click.

org.openqa.selenium.ElementClickInterceptedException: element click intercepted: Other element would receive the click: <div class="cookie-banner">
❌ Wrong
driver.findElement(By.id("male")).click(); // Fails — overlay intercepts!
✅ Correct
// Dismiss overlay first try { driver.findElement(By.id("cookieAccept")).click(); } catch (Exception e) {} // Then click the radio driver.findElement(By.id("male")).click();
✅ Fix: Dismiss overlays first, scroll element into view, or use JavascriptExecutor
 
🎯 Interview: "What is ElementClickInterceptedException?" — Another element is on top and catches the click event before the target element receives it. Fix by dismissing the overlay or using JS executor.
💥 Mistake 8 — NoSuchElementException

What happens

The checkbox or radio button does not exist in the DOM at the moment Selenium looks for it — usually a timing issue or wrong locator.

org.openqa.selenium.NoSuchElementException: Unable to locate element: {"method":"id","selector":"smsCheckbox"}
❌ Wrong
// No wait — element may not be ready driver.findElement(By.id("smsCheckbox")).click();
✅ Correct
WebDriverWait wait = new WebDriverWait( driver, Duration.ofSeconds(10)); WebElement cb = wait.until( ExpectedConditions .presenceOfElementLocated( By.id("smsCheckbox"))); cb.click();
✅ Fix: Use WebDriverWait with ExpectedConditions before interacting
 
🎯 Interview: "How do you handle NoSuchElementException for a checkbox?" — Use explicit wait (WebDriverWait + ExpectedConditions) to wait for the element to appear in the DOM before interacting.
🚫 Mistake 9 — ElementNotInteractableException

What happens

The element is found in the DOM but cannot be interacted with — it's disabled, hidden with CSS, or not yet visible.

org.openqa.selenium.ElementNotInteractableException: element not interactable — element is disabled or not visible
❌ Wrong
// Checkbox is disabled — click fails driver.findElement(By.id("promoCheckbox")).click();
✅ Correct
WebElement cb = driver.findElement( By.id("promoCheckbox")); // Check if enabled before clicking if (cb.isEnabled() && cb.isDisplayed()) { cb.click(); } else { System.out.println("Checkbox not interactable"); }
✅ Fix: Check isEnabled() and isDisplayed() before clicking. Scroll into view if needed.
 
🎯 Interview: "Difference between NoSuchElementException and ElementNotInteractableException?" — NoSuchElement: element not in DOM. NotInteractable: element exists but cannot be interacted with (disabled/hidden).
