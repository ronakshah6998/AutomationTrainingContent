TestNG Fundamentals & TestNG Annotations

Ditch main methods. Structure enterprise test suites, master the TestNG execution lifecycle, and construct professional test suites using hooks.

⚡ Lifecycle Hooks 🎯 Annotations 🎮 Interactive Playground 📂 testng.xml Setup
Why TestNG?

TestNG (Test Next Generation) is a robust testing framework designed to cover all categories of test execution: unit, functional, integration, and end-to-end.

💡
Why avoid standard Main methods? Using public static void main to run Selenium scripts forces linear execution, offers zero built-in assertion mechanisms, lacks parallel running options, and cannot isolate test run statistics. TestNG changes this entirely by managing the browser lifecycle and generating structured HTML reports.
🚀

Lifecycle Control

Allows pre-test setup and post-test teardowns at several modular levels using dedicated hooks.

🔄

Parallel Execution

Easily run test classes, methods, or entire suites in parallel across multiple threads with a simple XML flag.

📊

Built-in Reporting

Generates detailed default HTML and XML reports listing test passes, failures, and execution timings.

🎯

Smart Assertions

Built-in Assert classes for validating expectations without stopping your automation suite abruptly.

The TestNG Lifecycle Order

Annotations act as instructions telling TestNG when to execute specific code block scopes. Master this nested structure to build clean suites.

✅
Lifecycle Philosophy: Design your tests around the concept of nesting scopes. Suite wraps Test groups, Test groups wrap Classes, Classes wrap Methods, and Methods wrap the actual test scripts.
Execution Hierarchy Map
AnnotationExecution EventCommon Enterprise Use-Case
@BeforeSuiteRuns exactly once before any test suite in the XML begins.Initialise global databases, clear old test reports.
@BeforeTestRuns once before any class belonging to the <test> block runs.Read configuration properties, set environments.
@BeforeClassRuns once before the first test method inside the current class.Configure class-wide objects, logging dependencies.
@BeforeMethodRuns before every individual @Test method in the class.Launch browser instance, navigate to base login URL.
@TestContains your functional test script validation assertions.The actual step-by-step automation scenario.
@AfterMethodRuns immediately after every individual @Test method completes.Capture screenshot on failure, terminate/quit WebDriver.
@AfterClassRuns once after all test methods inside the current class complete.Clean up class-wide helper structures.
@AfterTestRuns once after all classes belonging to the <test> block run.Generate environment metrics, disconnect from server configurations.
@AfterSuiteRuns once after all suites mapped in the XML complete.Dispatch email/Slack reports, archive logs.

BaseTest Pattern & XML Execution Architecture

Production-grade automation frameworks never launch/close drivers inside raw test classes. Instead, inheritance models route clean setups.

🏛
Architecture Concept: Keep test classes clean by isolating environment parameters and driver creation tasks in a parent class called BaseTest. Standard test classes then simply inherit this logic.
1. Parent BaseTest Class Setup
☕ BaseTest.java — Class Framework Boilerplate
package com.framework.base;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;
import org.testng.annotations.AfterMethod;
import org.testng.annotations.BeforeMethod;
public class BaseTest {
code
Code
protected WebDriver driver;

@BeforeMethod
public void setUp() {
    // Initialize browser instance before every test scenario runs
    driver = new ChromeDriver();
    driver.manage().window().maximize();
    driver.get("https://app.example.com/login");
}

@AfterMethod
public void tearDown() {
    // Ensure resources are freed completely
    if (driver != null) {
        driver.quit();
    }
}
}

import com.framework.base.BaseTest;
import org.openqa.selenium.By;
import org.testng.Assert;
import org.testng.annotations.Test;
public class LoginTest extends BaseTest {
code
Code
@Test(priority = 1)

    driver.findElement(By.id("password")).sendKeys("secret123");
    driver.findElement(By.id("submit")).click();

    driver.findElement(By.id("password")).sendKeys("wrong");
    driver.findElement(By.id("submit")).click();

    Assert.assertTrue(errText.contains("Invalid Credentials"));
}
}

<suite name="Sanity Testing Suite" verbose="1">
<test name="Login Flow Executions">

</test>
</suite>
Common TestNG Execution Errors & Fixes

Avoid these four configuration mistakes that lead to broken builds and erratic test behavior.

🔴 Error: NullPointerException when calling driver action inside Test class

What happened?

You declared a global WebDriver driver; variable inside your subclass, which shadowed (overrode) the initialized driver variable located in the BaseTest parent class. The parent class initialization setup left the subclass's local driver variable set to null.

java.lang.NullPointerException: Cannot invoke "org.openqa.selenium.WebDriver.findElement(org.openqa.selenium.By)" because "this.driver" is null at com.framework.tests.LoginTest.testValidLogin(LoginTest.java:12)
❌ Wrong (Variable Shadowing)
public class LoginTest extends BaseTest { // REDECLARING VARIABLE WRONGLY: private WebDriver driver; code Code @Test public void testValidLogin() { driver.get("https://google.com"); // Throws NullPointerException! } }
✅ Correct
public class LoginTest extends BaseTest { // Do not redeclare driver here! code Code @Test public void testValidLogin() { driver.get("https://google.com"); // Uses BaseTest protected driver ✓ } }
✅ Fix: Subclasses automatically inherit parent variables. Avoid redeclaring class properties that are already initialized in Base classes.
🔴 Error: Tests running in unpredictable orders

What happened?

TestNG defaults test priority to 0 if not defined. When you mix prioritized tests with unprioritized tests, the unprioritized ones default to 0 and run first. This disrupts any logical flow you had planned.

[TestNG] Log: Execution running unprioritized methods before priority = 1. First execution completed: testTeardownVerification (expected last!)
❌ Wrong (Mixed Priorities)
@Test(priority = 1) public void testLogin() { ... } @Test // Defaults to priority = 0! public void testVerifyDashboard() { ... } @Test(priority = 2) public void testLogout() { ... }
✅ Correct
@Test(priority = 1) public void testLogin() { ... } @Test(priority = 2) public void testVerifyDashboard() { ... } @Test(priority = 3) public void testLogout() { ... }
✅ Fix: Explicitly declare priorities for every test method inside your class, or rely completely on independent executions.
🔴 Error: Parallel Execution Driver Interferences (Incorrect Hook Scopes)

What happened?

You initialized a single driver instance using a static variable or inside a @BeforeSuite / @BeforeClass hook, and then attempted parallel test method execution. Multiple threads began manipulating the same shared driver reference simultaneously, causing the browser sessions to crash.

org.openqa.selenium.NoSuchSessionException: Session ID is null. Using WebDriver after calling quit()? Or driver reference mutated by concurrent threads.
❌ Wrong (Driver inside Class hook)
// Thread-sharing issue: @BeforeClass public void setupBrowser() { driver = new ChromeDriver(); } // Multiple tests sharing one driver instance.
✅ Correct (Driver inside Method hook)
// Thread safe (one driver per test method): @BeforeMethod public void setupBrowser() { driver = new ChromeDriver(); } // Each test starts a clean, separate session.
✅ Fix: For standard parallel setups, initialize WebDriver inside @BeforeMethod to guarantee isolation across execution threads.
🔴 Error: Org.xml.sax.SAXParseException when launching TestNG XML suite

What happened?

The system failed to parse your XML configuration because of structure mismatches, or because the Document Type Definition (DTD) validation URL was missing or malformed at the top of the file.

org.testng.TestNGException: ParserException: org.xml.sax.SAXParseException: The content of element type "suite" must match "(groups?,listeners?,packages?,test+...)"
❌ Wrong (Bad Hierarchy/No DTD)
<suite name="MySuite"> <classes> <!-- Direct child tag mismatch! --> <class name="com.tests.MyTest"/> </classes> </suite>
✅ Correct (Strict Hierarchy with DTD)
<!DOCTYPE suite SYSTEM "https://testng.org/testng-1.0.dtd"> <suite name="MySuite"> <test name="Regression"> <classes> <class name="com.tests.MyTest"/> </classes> </test> </suite>
✅ Fix: Always include the strict DTD declaration block at line 1, and ensure that <classes> are always nested inside valid <test> tags.
Technical Interview Q&A

Prepare for automation engineering roles by reviewing these common TestNG interview questions.

❓ Q1: What is the primary difference between @BeforeTest and @BeforeClass annotations? ▼

@BeforeClass: Runs exactly once before the first test method inside the *current class* file executes. It belongs to that specific Java class.

@BeforeTest: Runs exactly once before *any class* defined inside the particular <test> block in your testng.xml suite file executes.

Scenario Example: If your <test> block contains three distinct class files, @BeforeTest runs only once total, whereas @BeforeClass runs three separate times (once before each individual class begins execution).

❓ Q2: What is the purpose of the testng.xml file in an automation framework? ▼

The testng.xml file is the main orchestration hub for your test suites. It provides declarative configurations that let you:

  • Define suite-wide configurations and group classifications to execute.
  • Pass global parameter values dynamically to Java class hooks.
  • Configure thread allocation sizes and parallel execution modes (methods, classes, or suites).
  • Include or exclude specific tests using package, group, or method name filters.
❓ Q3: How do you configure a test method to run multiple times consecutively? ▼

Use the invocationCount parameter directly within the @Test annotation.

☕ Invocation Count
@Test(invocationCount = 5)
public void testPaymentGatewayHit() {
// Runs 5 times sequentially
}

This is commonly used in performance test scripts, verification loops, or when testing flakey server APIs under load.

❓ Q4: How can we exclude or disable a specific test case from running? ▼

To disable a test, use the enabled = false property inside the @Test annotation definition.

☕ Disable Test
@Test(enabled = false)
public void legacyTestScenario() {
// TestNG skips this completely during test execution
}

Alternatively, you can exclude specific packages, classes, or methods dynamically using the <exclude> tags directly inside your testng.xml suite file.
